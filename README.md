# Вузоведия

Telegram-бот для абитуриентов: подбирает вузы по баллам ЕГЭ с семантическим
поиском по направлениям. ML-модель работает локально, без внешних AI-API.

Бот: [@Vuzovedia_Bot](https://t.me/Vuzovedia_Bot)

---

## Что умеет

- Подбор вузов: диалог из трёх шагов (город, направление, балл ЕГЭ)
- Семантический поиск: понимает неточные запросы ("лечить людей",
  "программирование", "айти", "data science")
- Пагинация результатов: по 5 вузов на страницу
- Избранное: сохранение вузов с возможностью удаления
- История поисков: последние запросы с кнопкой повторного запуска
- Аналитика: топ городов и направлений, динамика за 7 дней и за всё время
- Антиспам: автобан за флуд, глобальный лимит, стоп-лист мата

## Стек

| Слой | Технология |
|---|---|
| Язык | Python 3.11 (VPS) / 3.12 (Windows) |
| Telegram | aiogram 3.31 |
| ML | sentence-transformers 3.3, `intfloat/multilingual-e5-small` |
| Поиск | numpy (косинусная близость по 384-мерным эмбеддингам) |
| Хранение | JSON + SQLite |
| Прокси | aiohttp-socks + sing-box (SOCKS5) на VPS |

CPU-only, без GPU. Работает на VPS 1 vCPU / 1 ГБ RAM.

## Как работает поиск

Обычный поиск по совпадению слов не подходит: абитуриент не знает точных
названий специальностей. Поэтому используется семантический поиск.

1. Каждое из 1232 направлений кодируется моделью `multilingual-e5-small`
   в вектор из 384 чисел. Получается матрица 1232 x 384.
2. Запрос пользователя кодируется той же моделью.
3. Считается косинусная близость между запросом и всеми направлениями
   (эмбеддинги нормализованы, поэтому скалярное произведение = косинус).
4. Результаты фильтруются по трём правилам, от сильного к слабому:
   - точное совпадение слов запроса с направлением (rank 0);
   - семантическая близость ниже порога 0.35 и стем-оверлап: совпадение
     4-буквенных префиксов слов запроса и названий направлений (rank 1);
   - семантическая близость ниже порога 0.35 и запрос расширен через
     словарь синонимов (rank 1).
5. Сортировка по (rank, семантическая дистанция, балл).

### Словарь синонимов

Модель E5 плохо понимает короткие термины и аббревиатуры. Чтобы "ui", "web",
"лечить" находили нужные направления, используется словарь синонимов на ~50
записей. Он раскрывает пользовательское слово в корень из базы ("ui" ->
"дизайн", "лечить" -> "лечебное"). Поддерживается транзитивное раскрытие
до двух уровней: "web" -> "программирование" -> "программная".

### Калибровка

Логика откалибрована на 27 контрольных примерах: 17 позитивных (должны
находиться) и 10 негативных (не должны). Результат: 17/17 и 10/10.
Скрипт калибровки: `scripts/diag_search.py`.

### Кэш эмбеддингов

Матрица эмбеддингов сохраняется в `embeddings.npy`, метаданные в
`embeddings_metadata.pkl`. При старте проверяется MD5-хэш JSON-файла базы:
если он не изменился, индекс загружается с диска (~3 секунды) вместо полной
пересборки (~45 секунд).

## Антиспам

Все запросы проходят через middleware `bot/antispam.py`:

- автобан на 5 минут за 30+ событий в минуту от одного пользователя;
- глобальный предохранитель: 120 событий в минуту на весь бот;
- санити-чек длины: сообщения длиннее 200 символов отбиваются;
- стоп-лист мата в `user_handlers.py` регистрирует нарушение;
- флуд не засоряет лог: fallback-записи пишутся раз в минуту от юзера.

Админы освобождены от всех проверок.

## Установка и запуск

1. Клонировать и поставить зависимости:
git clone https://github.com/TimofeyDoroshenko/Vuzovedia-Bot.git
cd Vuzovedia-Bot
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

2. Создать `.env` в корне (по шаблону `.env.example`):
BOT_TOKEN=твой_токен_от_BotFather
HF_TOKEN=твой_токен_из_личного_кабинета_HuggingFace
ADMIN_IDS=123456789,987654321
PROXY_URL=socks5://127.0.0.1:10808

3. Запустить:
python main.py


При первом запуске бот построит индекс эмбеддингов (~45 секунд), при
последующих подхватит готовый из `embeddings.npy` (~3 секунды).

## Контроль качества

- Логирование с ротацией (`logs/bot.log`, 5 МБ x 4 бэкапа)
- Error handler гасит `TelegramNetworkError` до одной строки WARNING
- Rate limit: не больше одного поиска в 5 секунд на пользователя
- Валидация ввода: regexp для города, направления, балла
- Закрытый список IT-терминов на латинице (IT, QA, AI, Python, UI, UX и др.)
- Калибровка поиска на 27 контрольных примерах
- Линтер: `ruff check .` проходит без замечаний

## Принятые инженерные решения

### Почему numpy, а не chromadb

Изначально использовался chromadb с HNSW-индексом. Отказались по двум причинам:

1. HNSW избыточен для 1232 документов. Полный перебор numpy-матрицы
   1232 x 384 занимает доли миллисекунды.
2. Надёжность. chromadb пишет индекс асинхронно через фоновый компактор,
   и при жёстком завершении процесса индекс повреждается. Numpy-матрица
   это один `.npy`-файл, который либо цел, либо нет.

Вес матрицы в памяти: 1.9 МБ. Загрузка с диска: ~3 секунды.

### Почему multilingual-e5-small

- Мультиязычная: корректно работает с русским языком и понимает английские
  технические термины (IT, web, python), которые пользователи часто вводят
  вперемешку с русским.
- 384 измерения: компромисс между качеством и памятью.
- Вес около 470 МБ, влезает в 1 ГБ RAM VPS.
- Префиксы `query:` и `passage:` обязательны для моделей E5, иначе качество
  поиска резко падает.

### Почему не ChatGPT и другие LLM

Проект можно было бы построить на OpenAI API или GigaChat: отправил запрос
пользователя, получил осмысленный ответ. Мы сознательно отказались по трём
причинам:

1. Приватность. Тексты запросов абитуриентов не уходят во внешние сервисы.
2. Стоимость. Локальная модель E5 работает бесплатно, без лимитов и платы
   за токены.
3. Независимость. Работа бота не зависит от доступности чужого API и его
   тарифной политики.

Плюс для задачи "найти ближайшие по смыслу направления" семантический поиск
через E5 решает её точнее и быстрее, чем генеративная LLM: нам нужно
ранжирование, а не генерация текста.

### Сетевые зависимости

Бот не работает офлайн в буквальном смысле: ему нужен доступ к
`api.telegram.org` для обмена сообщениями. Но все AI-вычисления идут
локально. Единственное обращение к внешнему ML-сервису — это скачивание
модели `multilingual-e5-small` с `huggingface.co` при первом запуске.
Дальше модель кэшируется на диске и больше не требует сети.

### Прокси на VPS

С российских VPS `api.telegram.org` недоступен. Весь трафик aiogram идёт
через локальный SOCKS5 на `127.0.0.1:10808`, поднятый клиентом sing-box
(VLESS + Reality). Режим определяется автоматически по наличию файла
`/etc/sing-box/config.json`.
